# Design guidelines

Every design decision in the clinic inventory manager follows the [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines) (HIG) and the HealthOS design guidelines (`HealthOS/docs/design-guidelines.md`), which record the HIG sentences behind each house rule. This document records only what this app adds or decides differently. Check a page against both before calling it done.

Reference pages: Inventory and the Stock In / Stock Out dialogs were hand-refined first and are the model for everything else.

## 1. Lists and tables

Sources: Lists and tables; HealthOS §7.

- **One line per row, every table** (user ruling 2026-09-24, https://claude.ai/artifact/CjeJH1TiBegeUnEtxTBPKX). A cell never stacks two lines. Body rows are a fixed 48 px, set once on `table-body.svelte` (`[&>tr]:h-12`); cells are `px-3 py-2`, so a 32 px button or input fits exactly and a text-only row still measures the same. Pages add no `py-*` to cells. Skeleton rows inherit the height, so a placeholder table is the loaded table with bars.
- **A second line goes to one of four places**, in this order of preference:
  1. **Its own column** when it is a fact people scan or sort by: the request time became a sortable Requested column ("Today 10:32", "19 Sep 16:05"); the order badge and non-order reason on Inventory became an Order column, matching Price List and the Dashboard.
  2. **Inline after the figure** when it qualifies that figure: a small muted or tinted phrase, `text-xs` with `ms-1`, in the same cell. "23 Sep 2026 14:05", "24 Jun 2025 1 year ago", "12 Oct 2026 in 18 days" (`expiryNote()` in `utils/expiry.ts`, warning or destructive ink; `expiryBadge()` stays for dialogs). An overwritten payroll run is a neutral badge beside its saved time. A batch row reads "Batch 1 · received 14 Jan 2026".
  3. **A badge after the name** when it is the row's own state and only the exception needs marking, as HealthOS marks only an inactive patient beside the name: Inventory shows Low stock, Out of stock and Not tracked after the item name and nothing for In stock. Where every row is an exception (the Dashboard's To Order tab) the state keeps a `StatusDot` column.
  4. **Dropped** when another column or control already says it: the batch count (the chevron shows the batches), "No stock" (the badge says Out of stock), "Since {date}" on Employees (the date the record was added, not a hire date), and any explanatory sentence ("Stock Out takes the earliest expiry first").
- **No row stripes.** A row's state is the badge or dot in the row, never a coloured inset on the leading edge as well; the two said the same thing.
- **Names stay whole.** An item or person name never wraps or truncates in a table: the cell keeps the primitive's `whitespace-nowrap` and `Table.Root` scrolls sideways when it must, as every HealthOS table does. Pages add no `whitespace-normal`, `break-words`, `max-w-md` or `min-w-48` to name cells.
- **Remarks and notes truncate.** Secondary free text gets one line: the column head carries a percentage width, the cell is `max-w-0`, and the text sits in an inner `div.truncate` with the full text as `title` (table cells ignore `max-width` otherwise). The edit dialog still shows all of it. This is HealthOS's `max-w-xs truncate` with `title` on notes, widened to a column.
- **Column heads are sentence case in the body face, never all caps.** `table-head.svelte` carries HealthOS's head style (`text-foreground h-12 px-3 font-medium`, the table's `text-sm`), and `SortHeader` renders the same text with only the arrow added, so a fixed column beside a sortable one does not look like a different table. Plus Jakarta Sans sets capitals tightly, so an all-caps label reads cramped; that, and HealthOS's "No all-caps labels", rules out uppercase eyebrows anywhere (stat-card labels are plain `text-xs` muted text). Sortable heads sort what the column shows; when a column goes, its sort key goes with it (Inventory no longer sorts by status; the Low Stock and Out of Stock segments cover that).
- **All-caps data gets tracking.** Item names and unit codes arrive in capitals, and Plus Jakarta Sans sets capitals tightly, so `capsClass()` in `utils/text.ts` returns `tracking-wide` for a string that is entirely upper case and nothing for mixed case. It goes on name cells, the Change column, combobox items and `DialogSubject`. The data is left as typed: title-casing it, in the database or on display, would mangle "1OZ", "5MG", "IU" and brand codes.
- **A stock figure is `Quantity`** (`components/app/Quantity.svelte`): the number in the normal ink and medium weight, the unit code muted beside it, the pack size ("(100 TAB)") muted and `text-xs`, since it describes the item, not the count. "13 BTL (100 TAB)" set in one weight read as a single lump; the number is what a person came for. A second figure of the same item on the row (Reorder level, a batch row, On hand on Approvals) passes `pack={false}` so the pack size appears once. Tone goes on the number through `valueClass` (destructive when out, warning when low, success or destructive with the sign on Movements). Text figures that are not stock (money, counts) stay plain `tabular-nums`.
- **Dates and times in cells**: `formatDate` ("23 Sep 2026") for a date, `formatDayMonth` ("20 Sep") inside a badge or beside a time so it never pushes the next column, `formatTime` as the small qualifier after the day. Figures are `tabular-nums`.
- **Connection status is a quiet pill, not an alert.** A dropped Convex socket shows "Reconnecting…" in muted `text-xs` at the end of the top bar (`connection.isOffline`), and only after three seconds down so a blip never flashes it; the client reconnects and replays on its own. HealthOS shows nothing; this app commits stock counts, so a spinner with no explanation would be worse than a word. This is how Gmail, Slack and Linear do it: small, out of the content flow, and named for the recovery.
- **The Dashboard has no stock buttons** (user ruling 2026-09-25, https://claude.ai/artifact/X3fEAj6DtT589z1ZupwCMw). The purchaser and the store clerk share one login, and the purchaser never moves stock, so the Dashboard's rows carry only her decisions: Mark Ordered… and Not now on To Order, Change Order… and Not Ordered on Waiting for Delivery, nothing on Expiring and Not Moving. Stock In and Stock Out stay on Inventory. Mark Ordered asks how many, in the item's unit with the pack size beside the field; Stock In counts against that quantity and closes the order on its own, so a short delivery shows as "Partly received" rather than dropping the item back into To Order.
- **Row text buttons are outline** (user ruling 2026-09-25): two actions side by side in a row are both bordered, never one outline and one ghost. Ghost is for icon buttons, the More ellipsis, and Clear links in a toolbar.
- **Row hover** is kept (`hover:bg-muted/50` on `table-row.svelte`), unlike HealthOS: rows here carry inline buttons and an expandable batch list, so the tint tells a person which row the pointer is on.

## 2. Pickers

Sources: Pickers, Lists and tables; HealthOS §5 (patient picker).

- **Choosing one record is a search field that holds the pick** (`ItemPicker`, user ruling 2026-09-24, after HealthOS's patient picker): a text input with a search glyph; typing shows up to eight matches beneath it; a click, or Arrow keys and Return, chooses one, the list closes and the field becomes a block showing the whole name (wrapping if it must, never clipped in an input) with a clear glyph; a click anywhere on it starts a new search. An empty field means no choice ("Any item" in the Movements filter). The staff who use this app are not familiar with tech, and this is the search box they know from everywhere; a list inside a dropdown button, and before that an always-open list that only ticked a row, did not read as choosing. The New Request dialog and the Movements filter share it.
- **On-hand figures in hints are `Quantity` too** ("**1** BTL (1 OZ) on hand.", "**12** BTL left after this stock out."), so the number reads the same everywhere; error lines stay plain destructive text.
- **The unit sits inside the quantity field** as a trailing `InputGroup.Text`, pack size included ("BOX (20 BTL)"), so a typed "3" means 3 of that. The hint and the error repeat the full figure in a plain sentence ("5 BOX (20 BTL) on hand."); the pack size stays out of the picker rows, where it is noise before an item is chosen.
- **A picker row shows the whole name.** The one-line rule is for tables, where a row is a record among peers; in a picker the name is the thing being chosen, so it wraps rather than truncates (`min-w-0 flex-1`, `items-start` on the row, the check icon nudged to the first line). A quarter of item names run past 30 characters and the longest past 60, so a truncated row hid exactly the part that tells two strengths apart. The trailing fact is one compact figure (`Quantity` with `pack={false}`, `text-xs`, destructive when zero) and no word after it; what it means is clear from the field, and the Quantity field's description repeats the on-hand figure once an item is picked.

## 3. Hints and descriptions

Sources: Writing, Alerts; HealthOS §9.

- **A hint stays only when it changes what the person types or shows what will happen.** The live figure under a quantity field ("5 BOX (20 BTL) on hand.", "12 BTL left after this stock out.", "Deducts RM 12.00.") stays: it is the consequence of the number being typed. A sentence that explains how the app works ("filters apply page by page, so the total…"), restates the field ("Min and max, in the item's unit."), or restates the title ("Enter the clinic password to continue." under Sign in) goes (user ruling 2026-09-24). The staff are not familiar with tech, and a sentence they cannot act on is noise they still have to read.
- **A confirm dialog's description says the consequence in plain words**, one or two sentences, no jargon: "That month's saved payroll and its payslips are deleted. This cannot be undone.", not "frozen figures"; "Stock is deducted as soon as you approve."
- **Empty states keep their one sentence** when it says why the list is empty or what to do next ("Every tracked item is above its reorder level.", "Try another search or clear the filter.").
